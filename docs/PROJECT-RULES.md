# Project rules

Working agreements for this repository.

## What this project is
A learning-and-resume project: a real-time collaborative code workspace built on a hand-written RGA CRDT. The goal is understanding as much as shipping, so decisions are explained and the core algorithm is not hidden behind a library. Yjs is used only as a comparison.

## Rules
1. Read `docs/03-CRDT-DESIGN.md` before changing anything in `packages/crdt`. Do not change the ordering rule without updating that doc and the property tests.
2. The CRDT package must stay dependency-free and must never import browser or Node APIs. (`yjs` and `tsx` are devDependencies used only by `bench/`.)
3. The server treats operations as opaque JSON. It must not interpret CRDT logic, except where `docs/05-DATABASE.md` says otherwise.
4. Every CRDT change needs a property-based test (fast-check) that checks convergence under random delivery order, duplicates and delays.
5. Never invent benchmark numbers. Results in README or docs must come from a real run, with the date and machine noted. The README results section is generated by `python scripts/update_readme_results.py` from `docs/results/`.
6. Keep docs and code in sync. If a message format changes, update `docs/04-PROTOCOL.md` in the same change.
7. One commit per feature or fix, with a message that says why.

## Commands
- Install (pnpm workspaces): `pnpm install` at the repo root
- CRDT tests: `pnpm test:crdt` (`FC_RUNS=10000` or `pnpm test:crdt:full` for more schedules); typecheck `pnpm typecheck:crdt`
- Sync client tests: `pnpm test:client`; web unit tests `pnpm test:web`
- Web app: `pnpm dev:web` (needs the server on :8000); production build `pnpm build:web`
- Server setup and tests: `cd server && uv sync && uv run pytest`
- Server (dev, SQLite unless DATABASE_URL is set): `cd server && uv run uvicorn app.main:app --reload`
- Server lint: `cd server && uv run ruff check . && uv run ruff format --check .`
- Server against real services: set `TEST_DATABASE_URL` (postgresql+asyncpg://...) and `TEST_REDIS_URL`, then `uv run pytest`
- End-to-end: `pnpm e2e` (Edge by default; `PW_CHANNEL=chromium` after `playwright install chromium`). The two pages of a test share one localStorage, so each person must open their files before the next person loads (names are read when a file session starts).
- README screenshots: `SCREENSHOTS=1 pnpm --filter @rce/web exec playwright test -g screenshots` (writes docs/images)
- Database migrations: `cd server && uv run alembic upgrade head` (0002 adds workspaces); SQLite files are only created, never altered, so delete an old dev `.db`
- Load test: `pnpm loadtest -- --clients 50 --duration 30 --spawn-server` (`--chaos` for fault injection); full series: `node loadtest/run-series.mjs 30`
- Benchmarks: `cd packages/crdt && pnpm bench` and `pnpm bench:yjs`
- Compaction: `cd server && uv run python -m app.compact`

## Gotchas
- There is no Docker on the main development machine, so the Compose stack and Dockerfiles are verified by CI only. PostgreSQL 18 and Redis 5.0 (needs `protocol=2`; the server already passes it) are available locally; credentials live only in `server/.env` (git-ignored). Tests ignore `.env`.
- The repository path contains spaces: do not run commands through a shell that re-splits arguments (see `loadtest/run-series.mjs`).
- Benchmarks on the development laptop vary a lot between runs; compare only conclusions that hold across runs.
